# 06　切片、推草稿、真机

## 1. 切片（自动的，但要看懂它打印的东西）

`K.assemble()` 会调 `slicer.split()`，打印：

```
  切片     0–  846  元素  39  图  5  动画  29  29KB
  切片   846– 1696  元素  20  图  3  动画  15  10KB
  …
✅ 高 3638 · 正文 73KB · 图片引用 23 处
```

每一行要看：
- **图**：这张切片里有几张图。超过 26 张就危险（图片全加载完这张才开始动）。第一张切片最好 15 张以内。
- **KB**：单张超过 150KB 说明里面有大块转曲文字或被重复的元素。
- 某个元素明明只在一处出现，却让好几张切片都变大 → 它带位移动画但没写初始位置（见 docs/08）。

最后一行的**正文大小超过约 640KB 就推不上去**（报 45002）。先别急着删东西，按这个顺序查：
1. 有没有大块元素被切成两份（卡片、整段对白）。调 `slice_target`（默认 850）换一下切的位置。
2. 路径的小数位数：所有坐标都要过 `K.f()`。
3. 转曲的字数：能不能少几句。
4. 立体帧的动画标签：每帧一张图带若干 `<animate>`，帧多了也占体积。

切片的原理和三个坑写在 `slicer.py` 开头。

## 2. 推草稿

```bash
export WX_APPID=… WX_SECRET=…          # 见 docs/01
python3 cover.py out/preview.html 3.6 392          # 先有封面（见下面第 3 节）
python3 build.py --push "标题"                     # 新建草稿，media_id 存到 out/media_id.txt
python3 build.py --update "$(cat out/media_id.txt)"    # 之后每次改完覆盖同一篇
```

`--push` 做了四件事（代码在 `starter.py` 的 `main()` 和 `wxapi.py`）：
1. `localize()`：把正文里每个 `href="assets/…"` 上传到图床，换成 `https://mmbiz.qpic.cn/…`。按「文件名 + 修改时间」缓存在 `out/mmbiz.json`，没改的图不重传。同一张图出现多次时每处加不同的 `?v=n`。
2. `upload_cover()`：封面传成永久素材。
3. `save_draft()`：`draft/add` 新建或 `draft/update` 覆盖。
4. `check()`：把草稿取回来，数一遍 `svg / animate / animateTransform / set / rect / circle / path / image`，和本地对比。**每一行本地和草稿的数都要相等**；不等说明公众号删了东西，回去查 docs/01 第 4 节的禁用清单。

带视频：在 `assemble(..., tail="{{VIDEO}}" + 落版svg)` 里留占位，推之前：

```python
mid, vid = wxapi.upload_video(tok, "片子.mp4", "标题", "简介")        # 转码要等一两分钟
cover_url = wxapi.upload_image(tok, "视频封面.jpg")
article = article.replace("{{VIDEO}}", f'<section style="text-align:center;">{wxapi.video_iframe(vid, cover_url)}</section>')
```

本地预览里 `{{VIDEO}}` 可以换成 `<video src="片子.mp4" controls playsinline style="display:block;width:100%">`。

常见报错：

| 报错 | 意思 | 怎么办 |
|---|---|---|
| 40164 | 出口 IP 不在白名单 | 把错误信息里那个 IP 加进公众号后台白名单；或设 `WX_PROXY` 走白名单里的出口 |
| 40001 / 42001 | token 无效 / 过期 | AppSecret 不对，或被别处刷新了；重新跑 |
| 45002 | 正文太大 | 见上面第 1 节 |
| 45009 | 接口调用次数超了 | 传图太频繁，等明天；平时靠缓存别重复传 |
| 48001 | 这个号没有该接口权限 | 未认证的号；只能手动贴 |
| SSL EOF / 超时 | 网络抖动 | `wxapi` 自动重试 3 次，还不行就再跑一遍 |

**只存草稿。** 脚本里没有、也不要加「发布 / 群发」的调用。发布由号主自己在后台点。

## 3. 封面

```bash
python3 kit/cover.py out/preview.html <第几秒> <从哪个 y 开始裁>
```

裁出来是 900 × 383（2.35:1），对应画布上 750 × 319 的一块。

- 选开头那一幕、主角和主角色都在、构图完整的一刻。
- 主角色要睁着眼、站稳、没在做大动作。如果用了立体帧，算一下那一秒正好是哪一帧（`帧号 = int(秒 × fps) % 帧数`），避开眨眼帧。
- 封面是单独上传的一张图。正文里修了素材（补了缺口、换了角色），**封面要重截重传**，否则列表里还是旧的。
- 列表页会把标题压在封面左下角，那里别放要紧的东西。
- 朋友圈分享用的是 1:1 的小图，从封面中间裁，主体放中间。

## 4. 真机验收

电脑浏览器、iPhone 模拟器里的 Safari、安卓微信都能播，不代表 iPhone 微信能播。**以 iPhone 微信真机为准。**

怎么看：公众号后台 → 草稿箱 → 这篇 → 预览 → 发送到自己的微信号（要先关注这个公众号）。预览链接有时效，每次改完重新发。接口里的 `message/mass/preview` 多数号没有权限，老老实实从后台点。

看什么（从头到尾看两遍，第二遍中途往回滑一次）：

1. 打开后多久开始动？超过 3 秒 → 第一张切片的图太多。
2. 有没有哪一幕停在初始画面不动（窗是空的、卡片只有表头、人不出现）？记下是哪一幕。
3. 页面有没有按时自己往下长？有没有长过头露出一截空白？
4. 两张切片的接缝处有没有一条细线？
5. 字清不清楚？最小的字看得清吗？
6. 往回滑，前面的窗是不是还看得清（压暗没压过头）？
7. 手机发不发烫、卡不卡？

## 5. 某一幕在真机上不动

不要猜。用排除法，一次定位：

```bash
python3 kit/phone_test.py out/article.html 5               # 第 5 张切片（从 0 数）做成 5 个版本，先本地看
python3 kit/phone_test.py out/article.html 5 --push "手机测试"   # 推成一篇测试草稿
```

每个版本顶上有一根一直在走的红条，左边的黑点个数是版本号：1 原样 / 2 去掉对 y、height 的循环动画 / 3 去掉图片 / 4 去掉所有路径 / 5 去掉所有循环动画。发到手机上，看**哪几根红条在走**：

| 结果 | 结论 |
|---|---|
| 2 和 5 走，1、3、4 不走 | 就是 y / height 的循环动画。改成 `animateTransform`（scale 或 translate） |
| 只有 3 走 | 图片的问题：数量太多、有图加载不出来、同一地址重复引用 |
| 只有 5 走 | 某个别的循环动画有问题，把循环动画按属性分组再测一轮 |
| 全都走 | 这张切片本身没问题；问题在别处（比如它在等上一张，或者元素被重复收进来） |
| 全都不走 | 不是内容问题：检查这张的 `<svg>` 标签有没有被改坏、草稿标签数是否一致 |

样板项目在这个问题上花了一整天，排除了图片链接、标签被删、图太高、动画太多、图片太多、视频干扰，最后用这个办法一次定位到是 10 个做声波起伏的 `y` / `height` 循环动画。

测试草稿用完记得在后台删掉，别和正式稿混在一起。

## 6. 每一批改动的收尾

1. 把 `build.py` 复制一份到 `work/`，文件名带批次。
2. 生成，看正文大小和每张切片的图片数。
3. `frames.py` 截改到的地方，放大看。
4. `--update` 推草稿，标签数一致。
5. 在 `交接.md` 里记一段：这批改了什么、对方的原话、没做的和原因、备份文件名。下次接手的人（或者一周后的你）全靠它。
6. 告诉对方：改了什么、在哪看过、哪些没验、请他重点看哪几处。
