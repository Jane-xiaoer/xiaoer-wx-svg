# 03　取素材

所有素材放在 `assets/`。四类：场景窗的帧、人物姿态、主角色、道具。

## 1. 场景窗的帧

```bash
# 先在联系表上找到这场戏在第几秒
python3 kit/extract.py sheet 片子.mp4 40 12 4

# 抽指定时刻的帧 → assets/win/meet_0.jpg、meet_1.jpg …（默认 600 宽，JPG 质量 80）
python3 kit/extract.py frames 片子.mp4 meet 41.2 43.0
```

- **一个窗 2 帧就够**（一场戏的头和尾），慢慢来回翻，看起来就是活的。需要看清一个动作（合上电脑、关门）才用 3–4 帧播一遍。帧数多了手机内存和图片数都吃不消。
- 挑帧：两帧之间要有看得见的差别（人换了位置、手抬起来了），但构图不能跳（同一个机位）。有叠化、转场的帧不要。
- 尺寸：全宽的窗显示宽度是 690，素材 600 宽就够清楚。半宽的小窗 300 宽。
- 单张 30–60KB。整篇的窗加起来 1MB 以内。
- 如果片子的画幅不是 16:9，窗的宽高比跟着素材走，别拉伸。

## 2. 人物姿态

主线上那个人需要几个不同的姿态（样板用了 7 个：刚醒、穿外套、下坠 A / B、坐、趴、被搂着睡）。来源三种，按优先级：

1. **片子里直接有**：抽那一帧，抠掉背景。
2. **片子里有但被挡住 / 构图不合适**：用片子的那一帧当参考，另外生成一张同风格的全身图再抠。这是唯一可以「另外画」的地方，而且只限人物，不包括主角色。
3. **拼**：上半身用一帧、道具用另一帧，合成一张。

抠图：

```bash
python3 kit/extract.py cutout 原图.png assets/fall_a.png --w 620     # 要 pip install rembg
python3 kit/extract.py shrink assets/*.png                            # 已经抠好的图：量化到 256 色
```

没有 rembg 就用任何抠图工具，导出透明底 PNG，再跑 `shrink`。量化到 256 色体积能小一半以上，厚涂画风看不出差别。

抠完**一定要放到浅色和深色两种底上各看一眼**：

```bash
python3 kit/extract.py grid assets/fall_a.png      # 生成带坐标网格的大图，洋红色是透明区域
```

要看的：
- **有没有少一块**。抠图工具常把被前景挡住、颜色和背景接近的部分抠掉（样板里床中间的床帮没了，上线前才被发现）。少了就去找同一场景的另一帧，把缺的那块垫在下面合成，不要重新生成。
- **边缘有没有白边 / 黑边**。有就往里收 1–2 像素。
- **底边**。要压在地面线上的图，底边以下不能有半透明的残渣。

尺寸：姿态图在页面上显示多宽就存多宽的 1–1.5 倍。下坠的人一般显示 190–280 宽。

## 3. 主角色

**只用定稿的那一张（或几张）图，不重画，不让任何模型重新生成。** 重画出来的东西，片子主人一眼就能看出「不是它」。

- 要一张正面站姿（或蹲姿）的透明底图。缩到 240 宽左右存一份，后面量坐标方便。
- 如果它在片子里有几个固定姿态（站、蹲、趴），每个姿态一张。
- 它要动起来的做法在 docs/05。

## 4. 道具

外套、鞋、手机、叶子这类会单独飞的东西，各抠一张小图。简单的形状（一片叶子、一个圆点）直接用 SVG 画，不用图。

道具的两个坑：
- **别重复**。人物图里脚上已经有鞋，就不要再弹出两只鞋。加道具之前看一眼人物图里有没有。
- **大小要和画面里的一致**。场景窗的画面里她头上有一片小叶子，你另外叠一片大的上去就穿帮。要么让飞过来的那片由大变小落到准确位置后消失（画面里本来就有），要么别叠。

## 5. 素材清单和体积预算

| 项 | 建议 |
|---|---|
| 全篇图片引用 | 250 处以内（同一张图被多处用也算多处） |
| 单张切片里的图片 | 26 张以内，第一张切片越少越好 |
| 单张图 | 窗 30–60KB；人物 20–80KB；角色帧 10–20KB |
| 图片总下载量 | 4MB 以内 |
| 正文（不含图片本身） | 640KB 以内，主要是转曲的字和路径 |

图片是通过图床地址引用的，不算进正文大小；但图片数直接决定手机上多久才开始动。
