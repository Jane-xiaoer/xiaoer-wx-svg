# 从对方网站截帧，做「带图片帧的产品故事」

适合：对方有一个网站，网页上有 3D 模型或动画（three.js、WebGL、Canvas、CSS 动画都行）。
把它一段段截成帧，拼进公众号长图，读者往下拉，就看到这个产品在文章里真的动起来。
样例：`templates/storyboards/等轴测-小耳FM洗衣房.json`（洗衣机、戴耳机的小耳，都是从 fm.xiaoercamera.xyz 截的）。

没有网站、只有 App 截图或作品图：跳过第 1–2 步，直接把图按第 3 步的尺寸处理。

## 整体流程

1. **看懂网站**：打开源码，找到 3D 画布元素、相机、能触发动画的函数或按钮。
2. **写截帧配置，拍**：`python3 tools/web_frames.py capture 配置.json 素材/raw`
3. **合成**：`python3 tools/web_frames.py compose 素材/raw 素材/jpg --bg "#ECE4D5" --width 560`
4. **挑帧**：看 `素材/jpg/frames.json` 的 `segments`（或总览图 `_sheet.jpg`），每站选一段。
5. **写分镜**：从 `等轴测-小耳FM洗衣房.json` 复制改，`"assets": "素材文件夹名"`，帧路径写相对路径。
6. **生成、自检**：`python3 iso/iso_journey.py 分镜.json --grow --speed 0.8`，再用 `tools/frames.py` 截几屏看。

完整配置样例：`tools/examples/小耳FM-洗衣机.json`（真能跑，拍的是线上网站）。

## 第 1 步：看懂网站

```bash
curl -s https://对方网站/ -o /tmp/site.html          # 单页应用就再看它引用的 js
grep -o 'id="[^"]*"' /tmp/site.html | head -50       # 找 canvas 的 id（element 填 "#那个id"）
grep -n "PerspectiveCamera\|OrbitControls\|controls\." /tmp/site.html | head   # 找相机和控制器的变量名
grep -n "window\.__\|window\.[a-zA-Z]* *=" /tmp/site.html | head             # 有没有已经挂在 window 上的调试函数
```

要找到三样东西：

| 要找的 | 为什么 | 找不到怎么办 |
|---|---|---|
| 画布元素（`<canvas>` 或包着它的 div） | `element`：只截它，别的网页元素藏掉 | 不填 `element`，截整个视口（就没法透明底了） |
| 相机 + 控制器变量 | 锁等轴测视角 | 用 `patch` 在源码里加一句 `window.__cam=camera; window.__ctl=controls;` |
| 触发动画的函数或按钮 | 一步步「开门 → 放东西 → 开始」 | 用 `{"js": "document.querySelector('按钮').click()"}` 模拟点击 |

## 第 2 步：截帧配置（每个坑都踩过）

- **WebGL 页面一定要 `"webgl": true`**：无头浏览器没有显卡，靠 swiftshader 软件渲染。不开的话画布是黑的或空的。
- **网站会自己改视角**（窗口一变就重设 fov、鼠标拖动、自动旋转）：用 `camera` 锁住，每一帧都强制回到同一个位置。
  `dir: [1, 0.816, 1]` 就是等轴测方向；`fov` 越小越接近正交（20–30 合适）；`dist` 控制远近；`shift` 平移看的中心点。
  `controls` 填控制器变量，工具会把它关掉，免得它和锁相机抢。
- **主体被裁到边**：`compose` 会提示「⚠️ 主体碰到截图边缘（左）」。这时把 `viewport` 开大重拍（例如 900→1000 宽），别去缩相机。
  小耳FM 开门那一帧，红门圈就是这么被裁掉一块的。
- **动画太快拍不到**：截一张图要 0.3–0.5 秒。网站里的等待时间（`setTimeout(下一步, 2600)`）用 `patch` 拉长，例如拉到 15000，让中间那段多拍几张。
- **拍到了哪一步**：`probe` 填一句返回页面状态的 JS（例如 `JSON.stringify(app.state)`）。`capture.json` 里每张图都会记下状态，对着看就知道哪张是在洗、哪张洗完了。
- **透明底**：`transparent` 和 `hide_others` 默认都开，前提是网页背景没画在 WebGL 画布里面。要是截出来底色还在，就去源码里把 `renderer.setClearColor(..., 1)` 的透明度用 `patch` 改成 0。
- **patch 没生效**：看输出里有没有「⚠️ patch 没找到原文」。`patch_url` 要匹配主页面的请求地址（例如 `"**/fm.xiaoercamera.xyz/"`，或 `"**/index.html"`）。

## 第 3 步：合成（compose 自动做）

- 铺底色：`--bg` 填分镜 palette 的 `bg`（fm 配色是 `#ECE4D5`），这样帧和文章底色完全一样，看不出图片边。
- 阴影羽化：主体（不透明的部分）保持不变，只有半透明的阴影往边缘淡出，不会出现一圈硬边。
- 同一套帧用同一个裁剪框：所有帧取并集再裁，不会一张大一张小、跳来跳去。
- 尺寸：站点帧 560 宽，作品画 450×600，每张 jpg 十几 KB。整篇 100 多张图约 3–4MB 没问题；正文 HTML 要控制在 1MB 以内（图片不算在里面）。
- 输出的 `frames.json`：
  - `aspect`：填到站点模型的 `aspect` 参数（默认 0.7875，帧比例不一样就要改）。
  - `segments`：静止 / 局部在动 / 大动作三种段。例：洗衣机的「关门」是大动作，「洗」是局部在动（滚筒里在转），「洗好停住」是静止。
  - `edge_warnings`：哪几张碰边了。

## 第 4 步：挑帧

| 站点模型 | 放哪一段 | 小耳FM 的例子 |
|---|---|---|
| `fm_done` | 一个动作播一次停在最后一帧：开门、东西滚出来 | `still` 放动作前那张，`frames` 放「大动作 + 随后局部在动」那几张 |
| `fm_frames`（loop） | 一直在动的状态：在转、在洗、在闪 | 「局部在动」整段，隔一张取一张（16 张左右就够） |
| `fm_washer` | 能点的一站：点之前一直循环 `cover`，点了换 `wash` | `cover` = 放东西那几张，`wash` = 关上门的那一张 |
| `fm_paint` | 作品一点点长出来 | 渲染过程截 12 张（从空到满） |

帧太多会变慢：一站 8–16 张最合适，step 0.12–0.18 秒。

## 写法（这类文章怎么才好看，小耳反复改过的）

- **像聊天，别像说明书**：开场先问读者一句浪漫的问题（「你有没有想过，一首歌，如果能看见，它会长什么样？」），再引出产品。
- **让角色说话**：产品有吉祥物或形象就用上。每站旁边加一句短泡泡（「嘘——它在认真听歌呢。」），角色点一下会弹一下。
- **站点上不要写小字**：手机上读不清。参数、时长、格式这类说明（「4 分钟洗 90 秒」「支持 mp3、m4a」）一律不写，一站只留一句标题、一句副标题。
- **有成果就晾出来**：作品一幅幅「晾」上绳子（`gallery`），比放一张静态图生动得多。
- **留一个能点的地方**：「猜猜看」，点一下揭晓（不点几秒后自动揭开）。
- **结尾只放网址**：放大，中间一段用强调色，好记。价格、额度这类会变的东西不写。
- **事实只用对方给的资料**：网站上看到的功能、价格以对方确认为准。网站和产品说明对不上的，先问。
- **音乐 / 图片版权**：用别人的歌、图渲染作品，选 CC 授权的，并在文中署名（`gallery.credit`）。
