# 动效分镜写法（给任何模型看）

你的任务：把一个题材 + 一份事实资料，写成一份**分镜 JSON**。
渲染器会把它变成公众号里「会自己长出来」的 SVG 动效长图：每个场景占一屏，按时间轴自动播放，页面一屏屏变长。
**你只写文案和挑场景**，坐标、动画、配色全由代码负责。

## 铁律

1. **只输出一个 JSON 对象**，不要解释，不要 markdown 代码块。
2. **事实只能来自给你的资料**。没给的数字、价格、功能、网址一律不写，宁可少一屏。
3. **不给没有的功能编演示，不编数字**。演示用的示例内容（文件名、表格）可以编，但不能编出「找到 2 段」「本周 12 段」这种看起来像真实数据的数字；资料没说的能力（比如一句话换肤、AI 操控）不要写进 prompt。
4. 文案短：每个字段都有字数上限（见下表），超了会被自动缩小字号，难看。
5. 6–8 屏最好（每屏约 7–11 秒，总长 45–65 秒）。第一屏用 `collapse` 或 `receipt`（讲故事开场；方法 / 教程类没有品牌，用 `receipt` 当清单开场更自然），最后一屏用 `price` 或 `statement`。**别每篇都用同一套顺序**，按题材挑场景，硬件类多用 devices，工具类多用 window / agent / search。
6. 相邻两屏不用同一种场景，同一种场景全篇最多 2 次。题材不是软件就别用 window / agent / skin。
7. 中文为主，英文只用于品牌名、口号、格式名。不用 emoji。

## 顶层字段

```json
{
  "title": "推文标题（≤24 字，利益前置，带数字更好）",
  "digest": "摘要（≤50 字）",
  "theme": "graphite-green | ember | paper-red | ink-gold | violet-night | sage-coral",
  "cover_line": "封面上那一行（≤16 字）",
  "tail": ["正文末尾小字第一行（网址/平台）", "第二行（可选）"],
  "scenes": [ ...场景... ]
}
```

主题挑法：科技工具 → graphite-green / violet-night；热烈、生活、声音 → ember；人文、出版、克制 → paper-red；高端、发布会 → ink-gold。

## 场景（type 必填，其余字段按下表）

### collapse —— 开场：一堆东西被吸成一个品牌（必须第一屏）
| 字段 | 说明 | 上限 |
|---|---|---|
| intro | 开场痛点一句，3 秒后消失 | 14 字 |
| intro_sub | 痛点补一句 | 14 字 |
| tags | 8–16 个短标签（被吸走的「一堆东西」：旧工具、文件格式、麻烦事） | 每个 ≤5 字 |
| brand | 品牌名 | 8 字 |
| slogan | 可选。品牌已有的口号（会逐字打出）；**没有就留空，别替用户编** | 18 字符 |
| tagline | 一句话说清是什么 | 18 字 |
| subline | 平台 / 关键特点，用 · 隔开 | 26 字 |

### window —— 产品打开的样子（先只露内容，侧栏工具栏随后滑出）
| 字段 | 说明 | 上限 |
|---|---|---|
| kicker | 小标题 | 10 字 |
| title | 大标题 | 14 字 |
| window.tab | 窗口标题栏里的文件名 | 16 字符 |
| window.sidebar | 侧栏列表 5–8 项 | 每项 ≤9 字 |
| window.doc.title | 内容区标题 | 14 字 |
| window.doc.meta | 标题下一行（强调色） | 20 字 |
| window.doc.table | 可选，表格 2–4 行×3 列，首行是表头 | 每格 ≤6 字 |
| captions | 1–3 行说明，第 1 行白、第 2 行强调色、第 3 行灰 | 每行 ≤20 字 |

### counter —— 一个大数字滚上去 + 周围标签 + 一组柱子
| 字段 | 说明 | 上限 |
|---|---|---|
| kicker | 小标题 | 12 字 |
| number | 整数（资料里真有的） | — |
| suffix | 数字后缀，如 "+" "%" "倍"（可选） | 2 字 |
| caption | 数字下面一句 | 18 字 |
| tags | 围着数字漂浮的 6–10 个短签（可选） | 每个 ≤5 字 |
| bars | 柱子 [[名称, 数值], ...] 3–6 组，数值必须真实（可选） | 名称 ≤8 字 |

### blueprint —— 线稿一笔一笔画出来 + 下面一个齿轮转起来
| 字段 | 说明 | 上限 |
|---|---|---|
| kicker / title | 小标题 / 大标题 | 18 字 / 14 字 |
| art | `house` 建筑立面 / `device` 一台卡片设备 / `wave` 一段声波 | — |
| dim_w / dim_h | 尺寸线上的标注，**只写资料里真有的尺寸数字**（如 "6000" "3.2mm"），没有就不填 | 8 字符 |
| badge | 线稿下方的标签 | 14 字 |
| caption | 最底一句 | 20 字 |

### trio —— 三个大字砸下来 + 一条流水线（+ 可选一把锁）
| 字段 | 说明 | 上限 |
|---|---|---|
| items | 正好 3 个 {big: 1 个字最好, en: 英文, sub: 一句} | big 1–2 字，en 10 字符，sub 8 字 |
| flow | 正好 3 个流程节点（光点会沿着跑），可选 | 每个 ≤8 字符 |
| rows | 0–3 行说明 | 每行 ≤22 字 |
| lock_title / lock_sub | 可选。**填了才画锁**，只适合隐私 / 安全 / 本地这类题材；不相关就别填 | 16 字 / 22 字 |

### agent —— 终端里打一句指令，窗口里那句话被改写
| 字段 | 说明 | 上限 |
|---|---|---|
| kicker / title | 小标题 / 大标题 | 12 字 / 16 字 |
| terminal | 终端标题，如 "Claude Code" | 16 字符 |
| prompt | 用户对 AI 说的一句话（会逐字打出） | 20 字 |
| reply | AI 回一句 | 16 字 |
| doc_tab / doc_title | 被操作的文件名 / 文档标题 | 12 / 10 字 |
| before / after | 被改写前后的那句话 | 各 ≤20 字 |
| abilities | 4 个 [能力, 一句解释] | 能力 ≤9 字，解释 ≤14 字 |
| footer | 0–2 行收尾 | 每行 ≤30 字 |

### skin —— 一句话换肤：亮色窗口被一道光扫成暗色
| 字段 | 说明 | 上限 |
|---|---|---|
| kicker / title | 同上 | 12 / 14 字 |
| prompt | 用户对 AI 说的换肤指令。**只有资料明确说能用一句话换肤才写**，否则不填 | 18 字 |
| subtitle | 不填 prompt 时，标题下一句说明 | 20 字 |
| window | 同 window 场景的 window | — |
| caption | 换完后一句 | 26 字 |
| footnote | 最底一行灰字 | 30 字 |
| swatches | false 就不显示色点 | — |

### statement —— 万能一屏：大符号 + 几条要点逐条滑入
| 字段 | 说明 | 上限 |
|---|---|---|
| kicker / title | 小标题 / 大标题 | 12 / 14 字 |
| mark | 圆里的大字/符号（1–4 字，如 "0" "AI" "∞" "静"），不填就放品牌标 | 4 字 |
| points | 2–5 条要点 | 每条 ≤18 字 |

### price —— 价格卡收尾
| 字段 | 说明 | 上限 |
|---|---|---|
| kicker / title | 小标题 / 大标题 | 12 / 14 字 |
| cards | 1–2 张 {name, price, badge(可选), highlight(可选), items: 2–4 条} | name 6 字，price 6 字符，items 每条 ≤11 字 |
| note | 卡片下一句 | 26 字 |
| url | 网址（会逐字打出） | 24 字符 |
| footer | 最底一行 | 24 字 |

### receipt —— 账单从打印口吐出来，印章砸下（适合「以前要付钱 → 现在不用」开场）
| 字段 | 说明 | 上限 |
|---|---|---|
| kicker / title | 小标题 / 大标题 | 10 / 14 字 |
| receipt_title | 账单抬头 | 8 字 |
| items | 2–6 行 [项目, 右侧备注]，**备注别编价格**，写「按分钟」「另付」这类 | 项目 10 字，备注 6 字 |
| total | [左, 右]，可选 | 各 6 字 |
| stamp / stamp_sub | 印章大字 / 小字。印章盖在单子底边，会压住 total 那一行（本意就是把「每个月」盖掉）；关键数字别放 total | 4 字符 / 8 字 |
| captions | 1–3 行 | 18 / 26 / 30 字 |

放哪一屏都行（开场最顺）。不是「以前要付钱」的题材，就把账单当成「清单」用：items 写步骤或参数，stamp 写结论。

### devices —— 1–2 台设备蓝牙同步到电脑（波纹 + 飞数据点）
| 字段 | 说明 | 上限 |
|---|---|---|
| devices | 1–2 个 {name, sub, tag(可选，价格签), shape: card 卡片 / bean 胶囊} | name 12 字，sub 22 字，tag 6 字符 |
| target | {name: 电脑名, lines: 屏幕上循环出现的 1–3 行} | 每行 12 字 |
| captions | 0–2 行 | 22 字 |

### fanout —— 一段东西裂成很多张卡片飞出去（分类 / 场景 / 用途）
| 字段 | 说明 | 上限 |
|---|---|---|
| source | 中间那段东西的说明（**中间固定画一段声波**，声音 / 录音类题材最合适，别的题材也能用但图标不贴） | 16 字 |
| items | 4–10 个 [名称, → 产出] | 名称 6 字，产出 12 字 |
| captions | 0–2 行；note 底部一条强调 | 26 字 |

### live —— 现场会议（**可以点**：点「开会」揭开，点「？」揭开说话人；不点也会自己播）
| 字段 | 说明 | 上限 |
|---|---|---|
| speakers | 说话人名字（用角色：我 / 客户 / 同事，别用真名） | 每个 4 字 |
| lines | 2–5 句 [说话人序号, 这句话, 可选 "?"]，带 "?" 的说话人先盖住 | 每句 16 字 |
| highlight | 第几句（从 0 数）高亮成「被划中」 | — |
| notes | 右边笔记 0–4 条；tidy 笔记下按钮文字 | 12 字 |
| button / button_hint / auto_start | 盖板按钮字 / 提示 / 几秒后自动揭开 | 4 字 / 20 字 |
| system_audio / status | 顶部两个状态 | 30 / 6 字 |
| captions | 0–3 行 | 24 字 |

### search —— 搜索框打字 → 结果落下（命中词高亮）→ 问一句 → 待办打勾
| 字段 | 说明 | 上限 |
|---|---|---|
| query | 搜索词（结果片段里要包含它才会高亮） | 8 字 |
| results | 0–2 个 [标题, 片段] | 16 / 24 字 |
| ask | [问题, 回答]，可选 | 16 / 22 字 |
| todos | 0–4 条待办（会依次打勾划掉） | 18 字 |
| caption | 底部一句 | 30 字 |

主题另有 `sage-coral`（鼠尾草绿 + 珊瑚粉，温柔、生活、声音类）。

## 写法建议

- 结构：痛点开场（collapse）→ 打开的样子（window）→ 硬数字（counter）→ 核心能力（blueprint / trio / agent / statement 选 2–3 个）→ 收尾（price）。
- 没有价格资料就用 `statement` 收尾，points 写「怎么拿到 / 去哪下载」。
- 不知道产品界面长什么样时，window 场景照资料写真实的文件名和功能名，别编数据。
- 标题：利益前置 + 数字 + 动词，别用「赋能」「颠覆」这类虚词。
